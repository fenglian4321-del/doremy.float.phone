# Float 私人共享记忆：自动记忆与可视化纠错

> 阶段快照。后续新增管理、Orbis、Latent、用量和备份以 `private-memory-phase-4.md` 为准；此文保留当时实现边界。

2026-11-08 用户澄清后，以“**AI 默认自己保存，用户随时查看和纠错**”为主流程；逐条审核改为可选、默认关闭。本阶段仍只在私人分支本地，不连接 VPS、不读真实记忆或 key、不部署、不推送。

## 本轮实现

- 原有写入记忆工具的新默认为开启/auto，保留用户已明确保存的工具偏好；共享模式统一采用服务端可选审核策略，不再弹另一套聊天确认卡。
- 增加受源码指纹检查的 Ombre 扩展，直接调用正式 BucketManager。默认 AI 请求即保存；用户改正文和撤销均直接生效，不再要求二次确认。
- 新增“让 Float 使用这份共享记忆”。启用后，聊天工具、自动总结、自定义应用和现有 Float 现实桥等通用写入走同一服务；提示词及相关读取也走当前正式库。不是 Dawn 心潮主动消息桥已经联通。
- 共享失败不会自动写回本机旧库。旧库保留但不参与共享模式的新读写。原有本机长期容量整理也修正为只裁剪长期条目，不误删核心记录。
- 共享模式不另生成 Float 核心摘要副本；核心读取来自 Ombre permanent。确实只允许写核心的分线会保存一份 canonical permanent 记录，不同时保存长/核心两份。
- 原生 SurfacePolicy 控制自动读池，按预算和正文去重；每次从正式文件取得现行正文。实际选中的记录进行最佳努力激活计数，正常计数变化不触发编辑冲突。
- 手机可视化支持浏览、搜索、修改正文、查看来源/前后版本及撤销。编辑和撤销带版本；旧页面与后续修改冲突时明确拒绝。
- 提交先落耐久意图，再写正式文件，再写历史/回执；模拟“已写入但回执丢失”后重试不会重复创建。历史是审计快照，不成为另一份可编辑事实库。
- 服务凭据只在服务端。用户连接后得到 7 天 HttpOnly 会话，关闭面板仍可让 AI 工作；断开后停止该设备共享访问，不切换回本机。不同设备分别授权，共用同一服务策略和正式数据。

共享正式来源目前按一个私人 Ombre 实例共用，**不提供多用户或按 Float 角色隔离**，启用前有明确说明。可选审核覆盖经扩展 record 接口提交的 AI 内容，不强行改变 Ombre 原生或其他客户端的写入政策。

## 实施位置

- `lib/memory-storage.ts`、`lib/memory-service.ts`、`lib/shared-memory-client.ts`：统一来源、自动写入、现行召回与失败不回退。
- `app/api/shared-memory/route.ts`、`lib/server/shared-memory*.ts`：同源私有代理、独立口令/HttpOnly 会话、服务端凭据、v2 协议与有界请求。
- `components/memory/shared-memory*.tsx`：直接纠错、可选审核、共享来源开关、历史与撤销。
- `tools/float-memory-review/`：可选 Ombre 扩展、源码兼容检查、镜像覆盖层和标准库测试。安装说明见该目录 README；安装器不接受未知或有私改的源版本。
