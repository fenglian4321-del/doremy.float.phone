# 1.0.36：持续手机助手与角色保存

需要配套 APK 和本次网页源码；只安装 APK 不会更新 VPS 网页。

## 使用

在工作区的工具抽屉，或角色聊天的「聊天信息」中，展开「Shizuku · 手机助手」。首次在手机启动 Shizuku 并授权 Float，连接执行通道。选择是否允许角色聊天、是否允许直接打开应用，点击「启用持续模式」，核对原生确认框。

设置保存在本机原生私有存储。离开设置、发送下一条消息、关闭工作区或重启 Float 都不会清除。Shizuku 已运行且授权仍有效时自动重连；撤权/断连会终止当前操作，不会重放。手机重启后，非 root Shizuku 仍需用户重新启动，见 [Shizuku 官方说明](https://shizuku.rikka.app/guide/setup/)。

「添加允许的应用」使用本机选择器和原生确认，最多 16 个。角色可以先查询允许列表，再查询/打开其中的应用；工作区也直接提供同一能力。使用当前对话选择的模型，不额外调用 Codex。应用名、包名和结果会提供给该模型。允许列表与持续启用状态不从聊天备份迁移。

已实现的动作是列出允许应用、读取执行 UID/Android 版本、查询应用安装与启动组件、通过 ActivityManager 打开应用。原生按钮可直接测试，结果及最近记录在设置中可见。系统报告启动成功不表示完成应用内业务。此通道尚不提供应用内点击、输入、截图、私有文件或任意 shell。

## 执行与核对

每次操作有绑定实际会话、文档、授权修订和 UID 的一次性原生票据。客户端先保存待核对标记，原生先提交持久回执，再调用 UserService。配置变化、导航、停止、撤权和 Binder 死亡会使旧票据失效；90 秒到期后不能继续。结果不确定时保留回执，阻止同会话继续执行，用户在对应聊天信息/工作区工具面板核对实际手机结果后可清除等待标记。停止单次工作区不会关闭已经明确保存的持续设置；「停用并断开」会关闭。

旧的逐任务授权协议保留兼容性；新版默认界面改用持续设置。旧 APK 不会伪装支持新协议。

## 角色保存

新建角色点击保存后立即等待本机数据库成功写入，随后进入已保存详情；不再要求返回画布放置后才入库。写入失败时保留编辑内容并显示重试提示，避免虚报保存成功。新建草稿 ID 保持稳定，联系人页收到角色更新后刷新缓存。

## 验证与未完成的实测

- 实际角色 React 编辑器：新建、模拟数据库失败、保留草稿、重试、刷新、编辑覆盖。
- 实际角色工具执行器：私聊/群聊路由及允许列表限制；实际工作区模型适配器覆盖 OpenAI 兼容、Anthropic、Gemini 三种协议和 work/private 两种范围，检查原工具 ID。
- 持续模式的存储先于动作、权限/配置改变、停止、并发、回执未知与禁止重放；备份排除本机执行标记；既有工作区组合工具回归。
- 390px 浏览器实际工作区界面；TypeScript/Next 生产构建；Android Kotlin/Java 编译、固定命令策略、APK 证书/清单/DEX 验证。

浏览器测试使用独立合成存储，模型和手机 Binder 是模拟的，没有使用用户聊天、模型账户或真机。仍需在目标手机核对 OEM 的查询/启动限制、Shizuku 重启重连、原生确认框和从角色聊天打开应用。
