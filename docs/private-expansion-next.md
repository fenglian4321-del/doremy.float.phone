# 后续可扩展前端与独立工作区：需求与进展

2026-11-09进展：独立工作对话与服务端文字文件已有[第八阶段本地实现](private-memory-phase8-workspaces.md)，受控工作工具默认不接生活记忆。下文仍保留完整目标；手机、附件、工作MCP和AI私人空间的其余部分继续推进。只暂缓Operit市场研究/搬运/兼容专项，不暂停原有手机能力或Shizuku候选。

用户目标是 Operit 式高自由度：授权读写手机文件、可选 Shizuku、观察设备并参与生活、AI私人空间，以及与生活记忆隔离的任务工作区。本阶段优先完成阈值记忆，没有因此安装插件、APK、Shizuku、读取私人文件或开启读屏，也未授权对外发信/发帖。

## 先复用仓库已有实现

已有 `android-shell/README.md`、`NativeRealityBridge.kt`、`lib/shell-detect.ts`：FloatShell WebView及本机现实桥已存在。源码入口不等于目标手机所装APK具备该能力；需盘点版本、可信站点、已授权方法、系统权限、后台限制和真实设备回执，不能从零另造一套桥。

已有 `lib/tool-executor.ts` 的 `executeMcpTool`、HTTP/SSE会话与 `/api/tool-proxy`。下一阶段先审计其凭据归属、传输、工具循环、回执和取消，再补服务端配置与能力边界，避免第二个平行MCP客户端。当前路径不是所有外部插件均已适配的保证。

## 生活与工作隔离

计划增加显式模式/工作区ID，并由服务端在每个读写、检索和工具入口校验权限。工作模式默认禁止自动读取与写入生活 Ombre；工作历史、摘要、附件、临时索引、任务租约、缓存前缀和重试均独立，UI持续显示当前模式。工作内容导入生活库需要用户显式操作；隔离不能仅靠提示词或隐藏UI。工作自己的上下文仍消耗token，不能承诺免费上下文。

AI私人日记、项目与文件不是正式生活事实，不自动灌入记忆库；后续明确归属、可访问范围、编辑与导出。手机授权目录、本地工作区与VPS文件区分开标识；手机离线不得谎报本机读写成功。

## 设备能力差距与插件兼容

在现有桥上核对并补齐授权文件目录读写、可观察/操作/核对结果的UI闭环、可选Shizuku，以及插件宿主接口。[Operit官方说明](https://github.com/AAswordman/Operit/blob/main/README.zh-CN.md) 列有 ToolPkg、MCP、Skill 等扩展；应优先验证远程MCP，逐项匹配UI、provider、hook、runtime与Android专用能力。ToolPkg/QuickJS或Android宿主插件不能直接宣称在PWA运行，具体插件须有名单与版本再验证。

[Shizuku官方介绍](https://shizuku.rikka.app/introduction/)说明其通过ADB/root权限访问系统API；[设置说明](https://shizuku.rikka.app/guide/setup/)也列明ADB权限受限。因此普通无root模式不能当作读取所有应用私有数据的通行证。集成需原生宿主、可信来源、窄方法和参数/授权范围校验，不能向任意网页开放shell。

前台状态、通知、无障碍、屏幕捕获各自授权、可暂停和限定范围。生活感知按需或事件驱动，避免默认持续截图上传、每次采样都调用模型。高自由度以已明确授权范围为界，本次描述本身不授权真实抓屏、访问私人文件、发信发帖或账号操作。

## 模型调用与缓存

由当前聊天模型统一选择内置、MCP和可选执行适配器，再按同一 tool_call_id 返回；邮件/小红书/花园不固定分给Codex。普通聊天不强加前置规划或辅助总结调用。

“常两次调用”需运行轨迹区分：正常工具选择→结果续写、旧辅助模型、重试、重复请求、UI模型。后续每轮显示调用原因、provider/model、usage/cache字段及缺失状态，并补工具回执幂等与生成去重。稳定工具顺序、人格前缀和动态资料分层值得实测，但不能承诺换前端必然提高缓存命中。供应商缓存计数语义保持准确。
