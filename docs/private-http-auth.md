# 私人站点 HTTP 登录修复

2026-11-10，FloatShell 1.0.34/code33。纯 APK 原生修复，网页/API/VPS 运行代码未修改，不需要为此重新部署服务端或关闭认证。

1.0.33 主 WebView 没有处理 HTTP 认证回调，默认取消 Caddy Basic Auth 挑战，首屏可能显示 net::ERR_HTTP_RESPONSE_CODE_FAILURE。新版增加原生账号/密码框，只有本人手动点击登录才提交一次；不替用户填写、不自动重试密码、不调用模型。

认证只允许配置的精确 HTTPS Origin（含端口）、预期 host 和当前主文档导航。Android 回调没有请求 URL/帧信息，因此只在该 WebView 尚未加载任何子资源的主文档窗口接收挑战；发现子资源、跳转或旧导航就拒绝模糊挑战。已经进入网站后若认证过期，需本人在恢复页点击重新加载以创建新的 WebView，不能借同域子资源或不同端口的跳转复用凭据。

密码输入隐藏、禁用表单状态保存和自动填充，认证对话框启用 FLAG_SECURE。取消、跳转、Activity 销毁或渲染进程退出会取消旧 handler 并清空输入框；过期回调不能提交。每个导航最多3次本人提交，失败后的后续请求仍需手动输入。没有把凭据写入源码、URL、JS、日志、设置或应用凭据库，不读任何凭据文件；仅使用 HttpAuthHandler.proceed 交给 WebView 响应当前认证。WebView 自身可能在网络会话中缓存认证，不由应用持久化或读取。

主文档401/认证错误先延迟恢复页，给认证回调优先显示原生对话框；无挑战、失败或取消则显示手动重试入口，不自动加载循环。不改变 SSL 错误处理，不绕过 TLS 验证。

针对性 JDK 策略测试覆盖精确域名/端口、userinfo/HTTP 拒绝、跨域/子资源/旧导航、取消与销毁代际、三次手动重试、401在回调前后的完成状态和输入边界；静态检查原生 UI/handler/恢复页线路。真实 Kotlin/Java/APK 构建及官方验签另见交付 manifest。测试只使用合成账号字符串，没有读取或提交本人真实账号。仍需用户在真机自行输入账号，核对正确/错误密码、取消和重试。
