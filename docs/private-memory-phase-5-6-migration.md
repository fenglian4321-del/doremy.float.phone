# 第五、六阶段增量与迁移

部署聊天的旧冻结根为 `/opt/float-private-20261108/float-source`，基础同库API已由该聊天用明示虚构条目实测。**本地新代码不会自动进入该快照**。本任务不修改VPS、发布、推送或读取真实凭据。现网状态由共享根 LIVE-DEPLOYMENT.md 管理，不以历史报告“未部署”覆盖最新基础API结果。

源码增量归档和逐文件SHA-256清单由 `scripts/package-private-memory-increment.mjs --outdir <绝对目录>` 生成，只含固定白名单代码/模板/许可/说明，不含 .env、私有卷、实际token、聊天、node_modules或.next。它包含修改文件的完整现行版本，**不是可盲目覆盖的补丁**；没有读取服务器冻结文件，不能声称基线hash已经匹配。运维需比较清单与冻结副本，审阅原有私改，另建可回退新快照再重建。

1. 保持当前基础服务验收结果和回退镜像，停服一致性整卷/配置备份并校验可读；私有 provider env文件也必须保留。正文备份CLI有意不包含密钥，不能替代这一步。
2. 新Float镜像带入网关同源路由、固定工具、原循环接线、设置、用量单列和预算修复；保留 FLOAT_SHARED_MEMORY_PUBLIC_ORIGIN，勿退回比较容器内部URL或信任转发头。原有Cookie路径覆盖新子路由。
3. 独立低权限启动 Codex 网关（Node20.6+、已核对CLI、专用状态目录），仅本机监听。Next和网关必须处于可访问同一loopback的受控网络；普通bridge容器不能通过宿主机127.0.0.1访问它。由部署任务审核共用网络命名空间/主机网络等方案，未解决前保持功能关闭，不能对公网开放执行端口。网关与MCP、本人访问、review口令职责分开，勿读取或迁移官方 auth.json。
4. Ombre新覆盖层从**干净且源码指纹匹配的原生基础镜像**重建，不能直接叠旧 float-ombre-memory/env1 强过不同模块检查。新Docker入口与 register 已含 provider持久化等价修复；保留 FLOAT_MODEL_ENV_PATH=/app/buckets/.float-model.env 原私有文件，config.yaml仍管模型选择。不要再叠旧文本补丁或删除/覆盖私有文件。原生入口可能从持久代码卷启动，须验证实际运行代码与新能力，不能只看镜像tag。
5. 先保持默认 lexical-graph-v1 验证原有同库读写和恢复。语义模式必须显式填写模型、端点、向量维度和针对该模型校准的门槛，使用语义模板；可用变量名指向启动器加载的原生embedding key，不复制秘密到源码。若实际key失效，由用户走已提供私密配置工具更新；代码任务不代读或索取聊天粘贴。
6. 独立验收新网关：本人认证和公开origin → 两工具目录 → 原模型工具调用及匹配ID结果返回 → JSON/SSE → 用量分列 → 禁止动作/未知字段/跨站 → 超时/取消/重试。先明示虚构只读数据，不把CLI/MCP连通当作真实LLM工具循环已验收。
7. 独立验收语义：握手应报告 semantic-hybrid-v1，UI标明语义模式和供应商数据流；首次构建不锁纠错，未就绪报错；近义/无关查询、纠错、归档、删除、停用、故障不回旧向量，模型/端点/维度变更后重建。再实测真实供应商质量/速度和重启持久化，不能以虚构向量通过替代校准。
8. 新代码不迁移正文数据库，不清旧卷、不上传聊天。回退仍按正文+审计状态一致性规则，不把旧审计套新正文；保留原provider私有状态。新后台模型调用尚未并入全平台用量，主动/离线推送未接通，不能以本阶段完成替代这些验收。
