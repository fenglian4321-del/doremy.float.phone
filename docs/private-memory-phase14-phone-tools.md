# Phase14：本机目录 AI 受控闭环（网页原型，未做 APK/真机验收）

继续原 Float 仓库，保留 phase13 冻结包。网页和模拟验证可以单独交付；Android SDK 许可由用户本人另行确认，不能当作其余开发停止条件。本阶段未访问 VPS、手机目录或真实模型，未安装应用、打开权限或外发资料。

## 使用方式与范围

手机目录面板默认仍为手动模式。用户先用系统选择器明确授权本区目录，或手动查看本区已有授权，再明确选择一个目录。AI 没有选择目录/弹出授权工具，不会自动扫描已有授权。

“本次新消息使用 AI 手机目录”默认关闭，只在内存中保存一次授权；读写授权不跨工作/私人空间、换页或下一次消息。另有默认关闭的“允许 AI 另存手机新文件”，未选时模型只看见 list/read 两个 schema。开启后，该轮只声明 phone 工具，原 VPS 本区文件工具暂停，避免模型混淆执行位置。停用立即取消本轮等待；原生已提交的创建不能自动撤回。

正文会发送给用户为本区选择的聊天 API；API 的既有直连/代理传输路径不变。操作正文不独立写入 VPS 文件、操作日志、用量日志、KV 或生活记忆；最终回复照常保存为本区对话，可能含模型引用的资料。声明的“无网络回退”指文件执行不转交 VPS、MCP、生活工具或其他执行器，不表示模型推理离线。

三个固定工具只接受相对路径及必要的新建正文，不接受 scope、grantId、URI、URL 或其他目录标识。scope 和目录由 UI 授权会话固定。旧 APK/普通浏览器/错误协议或执行位置拒绝启用。API 禁用原生工具时拒绝手机模式，不偷偷变成文字动作。

## 执行与回执

- `phone_list_files`：一个目录最多128项，不显示截断清单。返回来自此手机的清单和原生回执编号。
- `phone_read_file`：先在本轮列出父目录，只读取清单中明确列出的 UTF-8 文字；txt/md/json/csv/log，每文件32KiB。资料标为不可信数据。
- `phone_create_file`：必须先列出父目录；同名拒绝。提交前再列目录，防止期间出现同名文件；不创建父目录、不覆盖、删除或移动已有文件。原生仍执行 create-only 和写后重新读取核对。

JS 客户端补强回执核对：固定 `android_device` 位置与协议之外，list/read/create 返回路径必须等于原请求；read 校验实际正文 SHA-256，create 校验原请求的 SHA-256 和 UTF-8 字节数。错误回执保留原操作等待标记，不声称成功。停止发生在摘要计算期间，也不能再提交新建。

每次操作前后及每次模型请求前后重新核对所选授权和会话；撤权、桥失效、页面 origin 变化或人工停用阻止后续动作和旧结果发送。最坏仍存在系统提供器已提交动作不可撤回的边界，UI 明示，不用“撤权”声称回滚文件。

每轮最多8个调用、整个任务最多8轮，最后一轮不再声明工具；重号、未知或跨位置工具整批拒绝。工具结果沿用原模型调用 ID；Gemini 保留 providerCallId/thoughtSignature，Anthropic 与 OpenAI 使用各自的原生结果字段。没有额外规划/总结模型。

## 中断与数据保存

phone 工具对话仅保留在当前页面的本轮消息数组，不提交后端 turn/tool 保存。VPS 保留原用户消息和最终回复，既有本区模型任务/租约继续使用。操作回执展示仅含调用编号、操作类型、完成状态、位置、原生回执编号或固定错误码，没有路径/正文。

工具任务开始前，KV 只写本区 runId+时间。缺失/错误/取消回执不继续请求模型，也不自动新建另一份文件。停止、刷新或换页后，恢复遇到该标记会拒绝自动重放：先手动核对原手机回执及文件，再结束原任务并明确发起新消息。已有原生新建恢复仍只读取原目标核对，不再次 create。最终回复已经提交但回包丢失时，恢复只核对服务端 complete，不重调模型/手机，并清除标记。
