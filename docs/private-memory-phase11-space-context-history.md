# 本区续聊摘要与文件版本

本阶段继续原Float二改，工作/AI私人空间均保持固定后端表、工具和路由，与生活记忆独立。第十阶段已由部署聊天报告上线；本阶段另交源码包，不修改冻结phase10 ZIP，不操作VPS。

## 单文件版本

每次成功人工或AI保存，当前正文和新增版本在同一SQLite事务中保存；已有文件首次被本阶段修改时保留其当时版本。新增固定表`workspaces_file_versions`、`private_spaces_file_versions`，名称由已校验的空间类派生，模型或请求参数不能指定。文件历史不进入项目列表、聊天提示或通用日志。

用户可查看当前文件历史、读取旧版预览，再“恢复为新版本”。恢复必须带当前版本、目标版本和恢复编号：当前版本变更就拒绝；成功写成下一版本，原版本保留。相同恢复编号重试返回原回执，不因后来人工修改而重复恢复；编号换参数则拒绝。界面在确认回执后重新读取当前文件，若文件随后又改了会说明并显示新版。未保存的编辑会禁用恢复按钮，AI没有历史恢复工具。

历史最多每文件128版、本空间合计8MiB（UTF-8正文计量），达到上限明确拒绝新增，不静默删除旧版。文件本身仍32KiB、64个/512KiB。上限会影响后续保存和恢复，需要导出保管或创建新空间；当前没有自动裁剪和历史删除功能。安装前已经被覆盖的版本无法重建。

归档空间可查看历史，不能恢复写入。SQLite一致性备份包含文件历史；普通空间JSON导出仍为当前文件、原对话及当前摘要，不含全部历史正文。

## 明确发起的上下文压缩

首次没有摘要，不自动额外调用模型。用户点击“压缩较早对话并启用”后，使用所选同一API配置和模型进行**一次额外请求**，不声明任何工具。普通聊天仍没有前置规划或自动总结；窗口不足会拒绝，不自动补模型请求。

服务端按原始用户轮次分组，最近四组完整保留；每次最多选择十组更早对话且任务资料不超过64KiB。已有摘要仅与尚未覆盖的较早消息继续合并。单组过大或没有待压缩内容时明确拒绝，用户可多次明确压缩剩余部分，不截断资料。

摘要输入仅本区旧摘要、所选本区原始消息和附件引用元数据，不重读旧附件正文、不自动读取文件、其他空间、生活记忆或心潮。提示要求区分用户要求和AI建议，保留目标、约束、进度、路径和未决事项，不把历史文件描述当作当前文件正文。

模型仅返回固定`float-space-summary/v1` JSON，绑定任务ID，1–12段；每段有本批消息ID或previous引用，已有旧摘要时必须承接previous；摘要合计8000 UTF-8字节。服务端重新验证结构、来源白名单、原消息前缀哈希与旧摘要版本，再与完成回执一起原子提交。引用验证能约束来源范围，不能证明模型释义完全正确，因此人可直接纠正摘要。

成功后仅未来新任务使用摘要加未覆盖原文；现有任务保持自己的固定输入。全部原始对话仍可查看导出，原200条/256000字节对话保留容量不变，不宣称无限聊天。摘要不进入正式记忆、Latent、文件列表或其他聊天。可单独停用，随后恢复发送全量本区原文，仍受模型窗口检查。

用户可编辑摘要，保存使用空间及摘要版本CAS，不能覆盖另一设备更新；未保存摘要会阻止继续压缩以免丢失编辑。人工编辑保留覆盖范围及原始来源哈希，并标记人工来源；后续压缩承接这份人工版本。进行中任务或归档状态不允许改摘要/开关。

## 失败恢复与兼容

摘要复用本区持久任务表，任务kind为compression，与普通聊天操作隔离。取消、关闭、90秒租约、心跳、显式接管、模型配置指纹和停止后旧结果拒绝沿用已有机制。普通聊天不能完成摘要，摘要不能执行文件工具。无效JSON/来源、网络故障或预算不足保留旧摘要和原文，不追加修复/规划请求。

发送回执丢失可按原编号核对；若任务已停止或租约过期，先取得新的执行标识再请求模型。提交成功但确认丢失后，恢复读取完成结果，不再次请求模型。取消后恢复可能重新请求尚未确认完成的那次模型，界面明确提示；没有保存原始回复到本机KV来假装实现模型侧恰好一次。

旧空间状态不需重写，旧聊天任务默认chat；新增SQLite表初始化时建立，旧JSON字段保持兼容。全部命名空间独立，即便空间ID、文件名和客户端编号相同也不能互读。当前协议仍v1，前后端需配套部署；旧客户端不会自动获得新增界面。
