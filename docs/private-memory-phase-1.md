# 私人共享记忆改造：第一阶段

当前改动只在私人分支本地，未部署、未推送，也未连接 VPS。

后续进展见 [第二阶段：Ombre 只读适配](private-memory-phase-2.md)。本文记录第一阶段交付时的边界。

## 已落实

入口：记忆 → 设置 → 本机记忆控制。

- 长期 / 核心记忆自动召回：默认开启。关闭阻止 `memory-service` 自动注入，保留面板浏览、手动检索和短期聊天历史。异步读取及 embedding 完成时重新检查设置。已经进入聊天上下文的内容不会被删除。
- 暂停程序写入：默认关闭。开启后，总结、核心提炼、AI 工具、自定义应用、现实桥经 `saveMemoryEntry` 保存时被阻止；总结管线在调用模型前也检查。保存前再次检查，覆盖生成期间切换开关的情况。只有面板手工保存显式通过 `userInitiated` 放行。数据库不可用会报错，避免误报保存成功。失败的总结不推进对应进度。
- 两个开关使用现有配置存储；旧配置保持原行为。它们是本设备设置，不承诺跨设备同步。
- 设置页说明心潮 / Latent 尚未接通，原有“共享”页签仍表示 Float 内共同事件。
- 用量解析补齐 OpenAI 兼容响应及 Gemini 的缓存/推理细项，统一类型传到日志；未知用量不补零，缓存/推理细项不加到总量。未提供 total 时保持未知。

暂停程序写入不是待确认审核队列；手动触发 AI 总结仍属于程序写入。短期历史及其他模块自己的数据存储不受这两个开关影响。

## 后续适配边界

- 需核对当前心潮的认证、正式记忆 CRUD、版本与候选审核 API，再接浏览、编辑、待确认、归档、历史撤销和跨设备读取。当前未新建独立的共享事实库，也未虚构 HTTP 端点。
- Latent 模式需正式库的版本检查与失效屏障，确保旧索引不可返回；当前没有可用的 Ombre / Latent 切换。
- Orbis 需先确认源码导出模式；尚未读取私密记忆，也未接受猜测格式的导入。
- 桥接需核对 SSE 与消费者/唤醒路径；当前未实现心潮主动消息或离线推送。
- 用量尚缺独立持久化账本、跨请求/日月聚合、失败与缺失标识、流式尾帧覆盖、Anthropic 缓存计数规则、余额与费用展示。当前调用日志有容量限制且包含原有调试内容，不应被当作隐私最小化的完整账本。
