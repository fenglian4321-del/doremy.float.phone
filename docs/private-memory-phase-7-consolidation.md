# 共享对话阈值整理（本地实现，尚未部署）

2026-11-09。继续原 private-custom 二改仓库；本阶段不修改 Latent 的来源、模式或参数，不访问 VPS、真实聊天、私人凭据或付费模型。

## 当前行为

- 共享模式停用旧的逐角色独立总结 API 调度、旧事件计数累加与旧「写入记忆」聊天工具；不自动生成 Float 核心副本。旧本机数据、配置、查看和导出仍保留，切回本机来源可使用。辅助总结 API 的旧绑定不删除，但不参与新共享流程。
- 每段单聊按 conversation ID + character ID，群聊按 conversation ID + group 分开保存设置、消息版本、进度与续聊缓存。用户发送一次计一轮；可改为消息组单位：用户发送与同轮每位角色的全部回复分别计一组。回复拆泡和重生成沿用用户锚点，不重复计新轮；编辑变成待复核组，不算新的发送。
- 默认自动整理、允许手动、20 用户轮；token 阈值 0 表示关闭。近期保留目标16组/6000估算token，输入批预算10000、摘要4000字。这些是本项目初始值，可按对话修改，不是照搬参考项目的生产参数或准确率承诺。
- 任一阈值达到后成为待处理任务。下一次自然聊天沿用当前绑定的 provider/API/model，在正常回复末尾附内部结构化决策。允许 `none`，没有长期价值则不新增事实。缺失、非法、取消或保存失败不会清零，不因缺少决策补调总结模型。
- 「下次回复整理」现在只排队；「立即整理」在确有待处理内容、已知窗口且没有运行任务时，显式调用当前聊天模型一次，不新增聊天气泡。自然工具循环仍可多轮生成；embedding 也可产生额外请求，不能把所有网络或模型请求概括成一次。

## 同库与恢复

新增 `.float-review/review.sqlite3` 两张控制表 `consolidation_scopes/jobs`。它们保存计数哈希、CAS版本、任务/租约、可恢复决策和独立续聊摘要，不持久化整份原聊天。正式事实仍经原 `ReviewService.record` 写入同一 BucketManager Markdown；星海可视化、人工纠错、操作历史、可选审核、归档与回收流程继续共用正式来源。

观察操作仅上传已发送消息组的ID哈希、正文摘要哈希、说话人、估算token和版本；生成只使用本设备实际已发送消息。最终提交选中批次的临时原文，由服务端重新计算哈希并检查逐字引语和说话人。只把被引用的证据文字、真实消息ID、设备时间和说话人写入事实来源。任务规则禁止从故事、人格或关系预设猜现实事实，摘要不能充当新事实证据。程序能验证格式、来源和并发版本，不能数学证明模型概括的语义；可选写前审核和人工随时纠错仍有价值。

任务单作用域互斥，90秒租约/30秒心跳；不同生成使用不同claim。新设备不得用旧正文覆盖另一设备的新版本或复活撤回消息。同一 scope/消息 ID 才能共享水位；本实现不负责同步两份独立本机聊天记录，也不是实时消息推送。

服务端先持久化决策，再按 `con_<job>_<index>` 幂等写事实。正式库版本围栏排除本任务自己的精确写入；人工编辑、归档、删除或其他正式变更会阻止过时任务覆盖。部分事实成功、回执丢失、最终摘要/水位事务失败均可恢复同一任务，不重新推理、重复写已成功事实或提前标记完成。摘要与水位最终在同一 SQLite 事务更新。预算只能处理前缀时保留已触发批次的待处理标记，剩余消息不会因低于阈值而搁置。

可选审核开启时任务等待同一候选，审核后恢复，不额外调用模型。另一设备可显式接管已形成决策的任务，或接管过期未提交任务；不会抢占仍有有效租约的生成。「结束任务」保留待处理进度与已经成功保存的正式事实，不暗中撤销或删除它们。

## 缓存、窗口和显示

续聊缓存逐片段记录来源链。消息编辑/撤回使相关片段失效。只替换来源哈希仍匹配、已经被有效摘要覆盖且位于近期保留区之外的旧消息；不删除聊天。正式事实和用户最近的明确纠错优先于摘要。

每个聊天 API 可填写 `contextWindowTokens`。未知窗口时不运行整理或压缩替换，保留普通聊天与待处理进度；手动立即整理会说明原因。已知窗口按完整供应商请求（含工具定义）、输出预留与1024余量检查。输入token是估算，不是供应商实测用量；近期目标不允许作为突破窗口的保底。媒体和各模型分词仍应以真实供应商验收。默认未指定输出上限时为共享任务设置2048上限；已有供应商实际输出设置参与最终检查。

动态摘要/整理任务放在稳定的前导 system 层之后、历史之前，避免 Anthropic/Gemini 把新任务降为历史中的 user。既有深度注入与角色规则位置不改。内部决策在插件、正则、聊天渲染之前剥离；流式一旦遇到私有开标记便隐藏整个尾部，JSON 内嵌闭标记或残缺 JSON 也不能泄到气泡。实际原文证据先验证，不经幻觉时间戳清理器改写。

共享设置显示自动/手动、计数单位、进度、待处理、上次成功、恢复和续聊缓存。输入预算、窗口、替换条数及来源数量只在折叠诊断里显示，不写入自然聊天。完整账单仍以供应商 usage 为准；保留原有 Anthropic cache 计数语义。

## 直接执行与 Codex 边界

记忆读取、检索、事实写入、阈值整理和上下文缓存走 Float 的受控直接路径及同源本人代理，不经过 Codex，也不把密钥或数据库交给浏览器模型。现有 Float 内置执行器、原生工具 tool_call_id 返回链不变。

此前 Codex 两项心潮只读原型保留为显式诊断；不在普通单聊/群聊工具列表暴露，普通上下文调用也被执行器拒绝。连接可用不代表邮件、小红书、花园等功能已经接通。这些能力不固定归属 Codex；未来按宿主使用内置、受控 MCP 或可选 Codex 执行适配器，决策模型仍为用户选择的聊天 API。若适配器另开模型推理，必须单独解释和计量。

## 设计参考（仅文档）

参考 [WrenWen 指定提交](https://github.com/ssxl0126/WrenWen/tree/b987ae0ae9154f782920062358ea693e8388d6a0) 的记忆系统与上下文装配文档，采用原话证据、稳定前缀与动态资料分层、相关性与预算约束等概念。没有复制代码、安装依赖、照搬多数据库架构、75分/80或120条配额、准确率宣传，也不采用“人格高于安全”或隐藏规则。正式永久记忆不由本整理器自动衰减、归档或删除；过时建议应可追溯、可撤销。

## 验收与部署边界

运行 `npm run test:consolidation`、既有 `test:private-memory`、Python unittest、TypeScript、character-id、lint、生产构建与隔离手机UI。合成测试覆盖四条实际模型HTTP路径、隐藏流、单次生成、失败保留、CAS、跨设备接管、审核、部分事实与水位事务恢复。真实 provider/model、真实聊天、目标 APK 与 VPS 新快照仍需部署任务单独验收。

前后端需要配套更新；新增路由 `/api/shared-memory/consolidation` 必须继续使用可信 `FLOAT_SHARED_MEMORY_PUBLIC_ORIGIN`、本人 cookie 与服务端 review token。仅此动作允许256KiB请求，其他审核写入仍限64KiB；模型调用前原文批次另限128KiB。源覆盖层仍只接受四份精确原生源码，增加复制 `float_consolidation.py`，不能强行盖旧覆盖层。保留 provider 持久化与原记忆卷。备份仍按原离线 Markdown+SQLite 流程，新增表由同一SQLite携带。

回滚前暂停程序写入并保存同卷备份。旧版本不会理解新对话进度，不得把已自动保存的事实误当未写入再跑旧批量总结；回滚也不删除新正式记忆。本阶段没有发布、推送、重建或修改服务器。
