# 第八阶段：独立工作区（本地，尚未部署）

在原二改 Float 中新增专用工作区入口。记忆库顶部可进入，工作/生活选择保存在本机，下次打开仍回到所选区域。工作区打开时卸载生活记忆面板；明确返回生活区才重新挂载它。没有把原来的生活聊天简单改名为工作聊天。

## 可用范围

- 新建、选择、归档/恢复工作项目；服务端保存工作对话与工作文字文件。同一私人实例的其他设备验证本人后可查看同一工作区。
- 选择现有聊天API与模型；要求已填写实际模型窗口。普通工作问题一次生成，不强加规划/总结请求；工作文件工具通过同一模型的原生调用循环执行，结果按调用标识返回。
- 固定三个工具：`workspace_list_files`、`workspace_read_file`、`workspace_write_file`。工作文件位于服务端独立命名空间，不是手机授权目录，也不是现有角色电脑的远端Worker目录。
- 人工编辑文件使用相同版本检查；AI旧版本写入返回冲突，不覆盖人工新版。支持停止、恢复同一任务、结束任务和导出当前工作区JSON。导出只含此工作区对话/文件，不含生活记忆或API密钥。
- 工作工具回执可展开查看完成/未执行、文件与版本；不能仅凭模型文字把冲突当作成功。
- 工作模型用量以 `source=work` 单列进入原有元数据账本；本地显示请求数和窗口估算。供应商未报usage时保持未知，不能当作完整VPS账单。

## 隔离不依赖提示词

`float_workspaces.py` 构造时只接收原review SQLite连接、写锁和错误类型，没有BucketManager、正式记忆检索器、HTTP客户端或设备执行器。它只允许工作区固定操作和三项工作文件工具；DTO拒绝额外字段，模型参数不能指定其他工作区、字符ID、生活来源、URL或任意命令。每次任务都绑定当前工作区，文件相对路径不能穿越。

新增 `workspaces/workspace_runs` 两张表，工作原始对话与文字文件不写Ombre Markdown、不进入生活记忆/Latent索引或阈值整理控制表。它们位于同一私人review SQLite的不同表；全实例SQLite备份会携带这些工作原文，工作区单独导出只包含所选项目。此版本不是多用户隔离或数据库加密方案。

工作区选择器只读取单独的项目摘要列，不为显示列表加载其他项目的完整对话/文件。旧本地工作表会保留原文并补齐摘要元数据，迁移不删除项目。

前端 `workspace-client.ts` 直接使用现有供应商请求适配器和usage传输，不使用生活聊天组装器、角色人格、生活短期时间线、插件提示词、旧通用工具执行器或Codex。所有工具实际执行均由服务端工作区分发器校验。工作原文不会写入通用API调用原文日志或本机KV重试缓存，KV只保留工作区模式和不透明恢复标识/模型配置ID。

现有日常聊天、星海可视化与正式记忆继续原路径；生活自己的后台活动不会把工作对话当作聊天源，因为工作内容不进入原chat-storage。其他现有应用还没有工作区权限适配，默认不在此工作工具列表开放。未来接入MCP、手机文件与设备动作时仍需逐入口增加工作范围校验，不能因已有私人身份就直接开放所有生活能力。

## 并发、恢复与版本

同一工作区只允许一个未结束任务，前端也阻止重复点击触发并行模型生成。发送前保存不透明clientKey/claim；如果发送回执丢失，后端lookup查同一请求，不缓存或重新上传未确认原文。服务器确认没有接收时清理发送标记，用户可重发；已经接受则恢复原消息。

模型工具轮先持久化，文件变更、工具回执及模型下一步上下文在同一SQLite事务提交。工具幂等键为任务+轮次+原调用ID，允许供应商在不同轮复用ID。重放不重复写文件；部分动作后取消保留已完成文件，恢复处理剩余动作。每任务最多8轮工具，之后允许最终文字回复，不执行第9轮动作。

90秒租约、30秒心跳；停止的任务不会被迟到心跳复活。恢复或过期接管使用新claim，迟到的旧模型结果不能写进新执行。仍有有效租约的其他生成不允许被抢占。恢复可能重新请求当前任务的原模型，UI明确说明；已形成回执的文件动作不会重做，无法承诺供应商在所有断网场景下不计费。

恢复核对API配置ID、provider、地址和模型指纹；API密钥不进入指纹或工作数据库，允许同一配置的密钥轮换。完成后保留最终工作消息和操作摘要回执，清理每任务重复的完整上下文及文件正文，避免复制历史造成平方增长。

## 供应商协议修正

工作循环复用原OpenAI-compatible、Anthropic和Gemini适配。按[Google官方Generate Content规范](https://ai.google.dev/api/generate-content#FunctionCall)，若模型给出函数调用ID，响应应对应同一ID。本次补全Gemini JSON/SSE的原生ID保留、历史保存与回传；无原生ID的旧响应继续使用内部ID匹配并按旧协议返回名称，不把生成的内部ID伪装成供应商ID。thought signature保持原样；无参调用保留空对象，不注入`noop`参数。未改变既有Anthropic usage/cache计数。

## 限额与当前边界

工作区最多200个；每区64个文字文件、合计512KiB，单文件32KiB。每区最多约200条工作消息、正文合计256000字节预留最终回复，超限明确提示导出/新建，不自动删除或截断。任务临时上下文另限1MiB。完整模型请求含工具定义、输出预留与余量做token估算检查，不把最近对话保底压过实际窗口。

尚未实现工作附件、独立压缩摘要、文件版本撤销、手机目录/设备动作、工作MCP、AI自主日记/私人空间管理或工作内容显式导入生活库。当前只做可用的隔离工作对话和服务端文字文件，其他原诉求继续分阶段推进。只暂停Operit市场专项，Shizuku仍保留为手机能力候选，GalateaGarden按原约定等Float可用后接。

## 验证与安装

`npm run test:workspaces` 启动本地临时SQLite后端，复用真实本人代理、工作客户端、三种供应商适配器及usage。所有模型和账号数据均为虚构，禁止任何生活BucketManager方法；测试普通单次生成、三协议工具往返、原ID/签名、旧Gemini无ID、无参工具、8轮最终回复、越区拒绝、配置恢复、丢失发送回执与原文不进入KV。

Python新增11项工作区测试覆盖隔离、CAS、作用域、重复发送、事务/回执、取消接管、旧心跳/旧模型拒绝、归档容量、工具上限和元数据迁移。另做390px真实React+客户端+临时后端的文件编辑/AI工具/导出/切换项目验收，并回归原记忆功能。

配套新增 `/api/shared-memory/workspaces` 同源本人入口，固定代理到后端 `workspaces` 动作，128KiB请求上限；其他写接口原上限不变。沿用可信公开origin、本人cookie与服务端review token，不额外开放数据库、URL或shell。安装器增加复制 `float_workspaces.py`，继续四源码精确校验，保留原provider持久化、Ombre卷、Latent选择和参数。

本地实现尚未部署，不访问VPS、真实模型或手机。更新需要部署聊天比较新旧源码、建立可回滚新快照并配套验收。第七阶段原ZIP保留为历史，本阶段源码包另行提供。回滚不会删除工作数据表；旧版本不能继续工作区任务，回滚前应停止任务并做备份。
