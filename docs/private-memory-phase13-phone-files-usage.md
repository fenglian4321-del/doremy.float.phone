# 第十三阶段：手机目录基础与调用原因

继续原Float二改，复用已有FloatShell的可信站点、顶层nonce桥和系统选择器生命周期。第十二阶段已由部署任务报告上线；本阶段不访问VPS、不安装APK、不操作真机权限或私人文件。这里区分网页验证、原生源码与实际APK能力，不能把源码存在称作手机已可用。

## 授权目录基础

新增`ScopedFilesBridge.kt`、独立Java策略`ScopedFilePolicy.java`，经原有`SecureJavascriptBridge(ShellBridge())`注册六个固定方法：能力探测、目录选择、提交、回执查询、只读核对和取消。没有新增裸JavascriptInterface对象，不向iframe分发nonce，沿用每次调用的精确可信来源与常量时间nonce检查；目录模块另外要求HTTPS来源。

采用[Android官方SAF目录选择流程](https://developer.android.com/training/data-storage/shared/documents-files)，只接受系统`ACTION_OPEN_DOCUMENT_TREE`返回的树URI，保留实际授予的可持久读取/写入标志。不要求新增全盘存储权限，不绕过Android11等系统的受限目录规则。原Manifest及其Android8/9旧图片导出写权限保持原状。

授权记录在App私有存储绑定**准确站点origin + work/private + workspaceId**。网页只得到opaque授权编号、标签和权限状态，不得到content URI。模型参数无法选择目录模块的命名空间；本阶段也尚未给模型声明这些目录工具。工作、私人同名ID不能互用授权，生活记忆工具没有新增目录入口。

固定操作只有授权列表、撤销授权、目录清单、文字读取与**创建新文件**。路径按名称从树根逐级解析，拒绝绝对路径、URI、`..`、编码分隔符、控制/双向字符等；解析使用[DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract)并核对树内子文档，不接收网页传来的原始URI，不使用原生File绝对路径、shell或网络执行器。

每目录最多128项，超过上限报错而不静默截断；文字仅UTF-8的txt/md/json/csv/log，每文件32KiB，无效编码/二进制/过长正文拒绝。首版不递归搜索、建目录、覆盖、删除、重命名或移动文件。新文件路径的父目录须已存在；目标同名就拒绝。提供器自动改名或写后校验失败会报告结果未确认，可能留有新建空/部分文件，不伪称事务回滚。

执行在有上限的本机单线程队列中。新文件提交前将请求编号、scope、原目标路径与预期字节/哈希存入App私有回执；不存正文。写后重新读取核对，成功才返回完成。请求/进程中断后，相同编号不会自动再次创建。用户明确点击核对时只读取原目标并比较预期哈希；匹配表示目标状态已核对，不等于证明第三方提供器实现了跨进程原子事务。

创建已提交时，停止等待不能撤回写入。无法确认时保留回执；可以继续核对，或明确清除本页等待标记后自行检查目录，不自动重新提交创建。App每次最多32个内存任务/授权记录、全局128个持久写回执；回执满会拒绝新建，撤销对应授权时移除其回执，不删除文件。撤销会使旧任务结果失效；没有其他同URI绑定时按实际持有标志尽力释放平台授权。

**提供器兼容性、Kotlin/Android完整编译、系统目录选择器、真实URI授权/撤销与断网行为尚未实测。** Android DocumentsProvider可以来自云盘，存在网络依赖；普通浏览器/VPS没有本机桥时明确不可用，不回退成服务端文件操作或伪称手机在线。恶意/不兼容第三方提供器不是本模块能保证的存储事务边界。

## 网页面板

工作/私人空间新增折叠的“手机授权目录”，与原服务端文件区分开。打开页面只检查桥能力，不读取目录；用户明确选择、列出、读取、编辑草稿后另存新文件。草稿不自动上传VPS、不注入聊天或正式记忆、不写正文到KV。空间切换会卸载该面板；scope由当前空间固定提供。

桥协议`float-shell-files/v1`、执行位置`android_device`、方法与返回字段白名单都校验。旧APK、普通浏览器、丢失回执、超时和权限失效分别显示实际状态；没有已完成回执不声称成功。停止/取消、同一回执核对、清除等待标记的含义都明确显示。

**本阶段是手动目录操作基础，尚未接AI自主目录工具循环。** 后续须在实际APK/提供器验证后，将受控目录工具及回执按当前空间绑定接入所选模型，不能直接开放给通用生活工具。现在不增加手机文件到服务端工作区的自动同步或导入。

## 用量调用原因

每条用量新增固定枚举原因，普通回复/首轮决策、群聊回复、工具结果续写、用户恢复、手动压缩、手动记忆整理、辅助生成、向量与工具执行分别标注。未标注/旧记录显示未知；原始提示词、错误正文和自定义任意原因不会进入此字段。

私聊/群聊的线下模式首轮和缺少摘要后的补提也分别标注。原`offlineSummaryRetry`开关及0/1/2次补提行为保持不变；这次只记录实际请求原因，不新增模型调用。阈值整理仍搭在普通生成中，不能把每个HTTP请求都解释成一个独立规划器。尚不能仅凭原因字段自动证明所有重试或重复请求，部分旧调用具体功能仍未知。

每次HTTP请求、缓存/输入/输出/缺失用量的计数规则不变；用量界面和导出显示原因。手机手动文件操作不调用模型，不编造模型Token或费用。

## 构建状态与可复现路径

源码APK版本更新到`1.0.30` / `versionCode 29`，applicationId、minSdk26、targetSdk34、compileSdk36及签名机制保持原配置。当前主机PATH中的Java是11.0.15，未找到Gradle，也没有已配置的JAVA_HOME/ANDROID_HOME/ANDROID_SDK_ROOT或常见SDK目录。因此**没有运行完整assembleDebug，没有APK产物或签名/真机验收**。

现有`.github/workflows/android-shell.yml`已增加目录静态契约与独立JVM策略检查，原有Java17/Gradle8.11.1/Android SDK构建和签名验证步骤保留。必须在本分支、当前源码上构建，不拿旧分支APK宣称新桥可用；本任务没有推送提交、触发Actions或读取签名密钥。

准备JDK17、Gradle8.11.1及Android SDK36后，可使用原流程：

```sh
# 在完整仓库根目录；SHELL_SITE_URL由部署者设为自己的HTTPS Float站点。
node scripts/check-android-permissions.mjs
node scripts/check-scoped-files.mjs --compile-policy
node scripts/test-scoped-phone-files.mjs
gradle -p android-shell assembleDebug
# 正式签名沿用已有环境/CI Secrets，不能把密钥放入源码。
```

或在用户原仓库手动运行Build Android Shell APK工作流，选择含本阶段源码的分支。覆盖安装需保持原签名，先比较证书与显式备份；不通过卸载/清数据迁移。没有实际APK与设备验证前，新网页会对旧APK显示未支持。
